# MECH DUEL 设计评审与开发路线

> 评审时间：2026-08-29 · 评审范围：全部代码（main / mech / ai / effects / ui / assets / sfx / settings）
> 结论：骨架是好的，打击感及格，但攻防博弈的"三角"缺了一角——目前是个能正常玩的游戏，还不是"有深度"的格斗游戏。

## 一、现状基线（已具备）

| 维度 | 状态 | 说明 |
|------|------|------|
| 核心循环 | ✅ | 菜单 → 对战 → 结算，三局两胜，60 秒/局，KO / 超时 / 双 KO 平局判定齐全 |
| 打击感 | ✅ | hitstop + 屏幕震动 + 受击白闪 + 浮动伤害数字 + 幽灵血条 + KO 慢镜头，组合拳完整 |
| 模式 | ✅ | 本地 2P、AI 对战、AI 演示模式（`--demo`） |
| AI | ✅ | 意图计划 + 反应性防御（预判近战起手格挡、光束来袭跳跃/格挡），且用虚拟 input 驱动，与真人输入同构 |
| 工程 | ✅ | `--selftest` 无头回归 5 项全过；数值集中于 settings.py 单一来源；build_exe.py 可打包 exe |

架构上两个值得保持的优点：

1. **AI 输出与真人按键同构**（虚拟 `mech.input` 字典）——后续做训练模式、录像回放、难度分级都不用动战斗核心。
2. **数值全部走 settings.py**——平衡性调整有单一入口，阶段 4 的"AI 胜率回归"因此可行。

## 二、核心设计问题（按严重程度排序）

### P0-1 格挡无解，攻防三角断裂 —— 最优先

现状：格挡 80% 减伤、不耗资源、无破防手段、无削血。

推论：对手按住防御键站桩，近战 12 伤害被挡剩 2、光束 6 剩 1，**防守是严格占优策略**，博弈不成立。

修法三件套：

- **投技**：无视格挡、伤害中等、可被跳跃躲。投克挡、挡克打、打克投，三角闭环。
- **格挡削血（chip damage）**：格挡命中仍掉 1 血，低血量时"挡到死"不再是安全牌。
- **破防值槽**（可后置到阶段 2）：连续格挡积攒破防值，满则 GUARD BREAK 大硬直。

### P0-2 跳跃没有攻击，跳入进攻不存在

空中只有水平移动（`mech.py` 空中分支），跳跃纯粹是逃跑/躲弹手段。经典格斗的空间压制核心"跳入重击 → 地面压制"整个缺失。

修法：加**空中下劈**，命中带小浮空——直接为阶段 2 连段系统铺路。

### P1-1 没有连招系统

受击硬直 15 帧，斩击整套 28 帧 + 冷却 18 帧——单发命中后双方谁也接不上谁，战斗是"回合制互换"而非压制与逃离。

最低成本引入：**命中后允许取消**（斩击命中帧内可接光束/跳跃），先做出 2-3 个实战连段，再谈浮空与受身。

### P1-2 能量经济太浅

能量只干一件事：放光束（消耗 35，0.22/帧回复 ≈ 5 秒回满）。没有"攒大放小"的取舍。

修法（阶段 2）：能量升级为超必杀资源（满 100 释放机体专属超必杀 + 演出）；光束改为短 CD 弹药制。

### P2-1 角色差异化只有数值

GARNET / AZURE 共用全部动作骨架，差异是"重装 vs 轻装"数值换皮。格斗游戏的生命线是**招式差异**。

修法（阶段 3）：加第三台机甲时必须同步配专属特殊技（如 GARNET 装甲冲撞、AZURE 二连光束），否则加角色只是加数值行。

### 顺带记录的小问题

- P2 按键映射（小键盘 1/2 与数字排重叠）容易误触，阶段 4 做重映射时一并解决。
- `mech.py` 的 `_stun_extra` 用类属性兜底 + 实例覆盖，能用但脆弱，重构状态机时顺手改成 `__init__` 里初始化。
- `ui.py::banner` 的 `pulse` 参数当前是空实现。

## 三、落地计划

### 阶段 1 · 攻防闭环（P0，1-2 次迭代，先做这个）

| 事项 | 内容 |
|------|------|
| 投技 | 近身指令（melee 长按或独立键），无视格挡，可被跳跃躲 |
| 格挡削血 | 格挡命中掉 1 血（chip） |
| 跳跃攻击 | 空中下劈，命中带小浮空 |
| 冲刺/后撤步 | 双击方向或独立键；后撤步带短无敌帧（简化版 dodge） |

代码落点：`mech.py` 状态机新增 `THROW / DASH / AIR_MELEE` 三态；`main.py::_combat` 加投技判定；`settings.py` 新增对应数值组；`ui.py` 菜单帮助文字同步更新。

**完成标准（selftest 新增用例）：**
1. 格挡状态被投技命中 → 正常掉血
2. 格挡光束 → 掉 1 血（chip）
3. 空中按下攻击键 → 进入 AIR_MELEE 且有判定盒
4. 后撤步期间被光束命中 → 不掉血（无敌帧验证）

### 阶段 2 · 深度系统（P1）

1. **命中取消**：斩击命中帧内允许接光束/跳跃 → 实战连段成立
2. **浮空与受身**：空中受击进入浮空态，可追打；受身键提前落地
3. **超必杀**：能量满 100 释放，机体专属演出（hitstop 放大 + 变焦，现有 Fx 系统能撑住）
4. **破防值槽**：HUD 加槽显示，GUARD BREAK 大硬直

### 阶段 3 · 内容扩展（P2）

- 第三台机甲 + 每台 1-2 个专属特殊技（招式差异，不是数值差异）
- AI 难度三档：现有概率参数整理成难度表（反应概率/决策间隔/失误率），架构不动
- 训练模式：无限时间、判定框显示（`melee_hitbox()` 现成）、帧数据显示

### 阶段 4 · 打磨发布（P3）

- 按键重映射 + 手柄支持（pygame.joystick，成本不高）
- BGM 与音画打磨
- **平衡性回归**：selftest 加"AI vs AI 跑 100 局统计胜率"，任意一方超出 45%-55% 区间报警（对战模拟已能全链路无头运行，此功能可做）
- KO 高光时刻回放 / 慢放

## 四、执行原则

1. 每个新系统落地时**同步补 selftest 用例**，保持无头回归可跑。
2. 平衡数值**只改 settings.py**，禁止散落在逻辑代码里。
3. 阶段 1 的投技是唯一"不做就没法叫格斗游戏"的东西，其余均可排后。
